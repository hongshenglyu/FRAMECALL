## 2｜本轮预期行为与状态规则

### A. 取消优先与状态线性化

- 设计并实现可审计的**状态迁移允许表**（PENDING、RUNNING、CANCEL_REQUESTED、CANCELLED、SUCCEEDED、FAILED及01-05已有attempt字段/未知结果占位），标明哪一行或条件更新为状态转移的**线性化点**。
- 对同task取消与AI完成并发执行，必须在同一DB锁或等效原子条件更新下建立确定性顺序：**取消请求若已被持久接受，则后续AI成功结果不得再写SUCCEEDED、新事件、旧结果路径或100%完成**。如果“完成”已先提交，后续取消必须明确非成功取消（例如409），不能伪称已取消。
- 取消重复点击要有确定语义；不得因重复请求将终态变回RUNNING/PENDING，或把`CANCELLED`改为`SUCCEEDED`。HTTP状态、任务/attempt状态、用户可见进度必须彼此一致。
- 不得把取消外部AI服务HTTP请求放在长期数据库事务中；明确远端取消成功、明确失败、超时/断联（结果未知）的处理：**不确定远端是否停止时保留安全隔离/人工复核状态和活动占位**，不得允许运行新的attempt。

### B. 进度与回调一致性

- `updateProgress`采用短事务，核验currentAttemptId/有效授权/合法状态、阶段与百分比的合理范围，以及取消优先屏障；取消已接受后旧进度不应覆盖CANCEL_REQUESTED/CANCELLED或任务错误码。
- 同一个attempt的重复回调、乱序百分比、旧attempt的有效格式回调、完成/失败后回调均要有明确并测试过的响应语义；可采用版本号/单调进度、条件更新或等效保证。不要假设HTTP到达顺序就是生成顺序。
- 用户详情轮询在AI长请求期间仍能观察到已提交进度，不能因为持有长事务或阻塞的HTTP线程而不可查询。

### C. 尝试/终态/幂等闭环

- 01-05真实持久化attempt、同task一次活动attempt和有界后台队列必须保留。新增取消优先规则不得破坏20并发重试、旧attempt回调拒绝或失败后合法重试。
- 明确cancel后何时允许新attempt：必须已确认本地与远端执行不再产生写入；若不确定，维持隔离拒绝重试409，直至人工核实并经单独审核恢复。
- 稳定处理调度提交拒绝503、AI显式503、连接断开、读超时、工作线程异常、回调时序与数据库事务失败。非秘密错误码可审计，内部堆栈和原视频路径不能写入客户端响应。
- 当任务有旧人工复核与媒体时取消或失败，不得删历史；01-07仍负责后续完整生命周期。

## 3｜必须执行的隔离并发与回归测试

| 主题 | 必需证据与断言 |
|---|---|
| 取消先于完成 | 使用CountDownLatch/线程屏障固定竞态顺序；取消提交后晚到SUCCEEDED必须被拒，未新增事件或覆盖媒体，任务/attempt最终与取消语义一致 |
| 完成先于取消 | 成功已提交后再取消，返回可解释的冲突或无效操作，不把既有成功伪改为CANCELLED |
| 并发取消与重试 | ≥20个并发混合/重复请求，仅合法转换生效、DB任务/attempt记录无双执行；与01-05 20次重试回归区分统计 |
| 进度回调错序 | 当前attempt进度不同顺序、重复回调、旧attempt有效token、已取消/已终态后回调，不得倒退或越过取消屏障 |
| 远端取消结果 | 显式成功、503、连接断开、超时；不确定状态不能允许自动重试、不能误报取消已生效 |
| 队列/失败/重启 | 排队中取消、运行中取消、超时占位、启动遗留、线程池拒绝；有确切记录和重试规则 |
| 权限 | 用户B、匿名不能取消或重试A任务，ADMIN/指派裁判按01-01权限定；被拒请求零副作用 |
| 兼容性 | Spring旧01-01～01-05所有可执行测试、AI安全测试、真实回环合成Mock进度链、前端生产构建和合成Chrome媒体回归重新运行 |

- 至少提供**任务ID、attemptId、线程名、阶段、请求/DB事务顺序、实际HTTP状态、真实状态与新增事件数**的脱敏证据。不能仅以一个布尔PASS替代实际的竞争次序证明。

- 若迁移Schema，限合成H2执行并提供增量/存量兼容结果，MySQL只提交评审脚本，不在实库执行。
