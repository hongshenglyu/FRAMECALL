## 2. 目标行为：独立异步调度+幂等重试

### A. 真实独立异步执行

- 必须让任务创建和合法重试请求**快速返回**，分析在真正独立的执行器/组件/队列中运行，不能靠同类内部调用`@Async`造成同步执行。
- 明确任务执行入口、线程池/任务队列生命周期、容量/饱和处理、失败提交回滚及日志。禁止无限线程/无限任务队列，禁止把阻塞外部AI调用保留在请求事务中。
- 若当前技术栈无法支持跨进程持久队列，不得伪称生产级“持久化调度”：明确区分**单实例进程内异步**与**数据库级跨进程幂等**；对服务崩溃和重启后的未完任务给出状态/恢复策略和未验证边界。

### B. 运行尝试attempt与幂等性

- 设计并按最小必要范围实现真正用于持久关联的`attemptId`（或等价唯一运行标识），避免只在内存里新增一个变量却无法约束并发重试。记录taskId、attemptId、状态、创建/开始/结束时间、错误原因必要字段及迁移方式（以真实现有Schema为准）。
- 原始创建及重试应维护明确的**合法状态允许表**：例如仅指定终态`FAILED`/`CANCELED`允许按授权策略发起新尝试；运行中、排队中、完成中重复点击不得产生两个并行执行。不要凭用户输入跳过后端鉴权。
- 幂等检查必须是**数据库原子更新/约束**或同等可验证事务级方案，而非先查再写的竞态。若支持请求`Idempotency-Key`，明确其作用域、冲突语义和重复请求返回；若不支持也必须约束同task仅一个活动attempt。
- 保持历史事件、复核记录不因重试而无声丢失；若需决定其保留/清理策略，记录为01-07待做事项，本轮**不得删除历史复核**。
- 与01-03现有回调grant及固定回调/存储根相兼容。旧attempt迟到的回调不能被当作当前attempt的正常完成；本轮可提供最小关联/拒绝机制，但01-06的取消优先、终态状态机仍要后续专项完整验收，不得宣称已解决全部竞态。

### C. 危险情况必须fail-closed

- 线程池拒绝、队列满、调度提交失败、AI端返回503/连接失败、回调超时、服务重启、中途异常、两个请求同时重试等，应保持可查询的有界失败状态，不得返回成功但实际没入队，亦不得留下重复运行。
- 不向客户端暴露内部栈、外部密钥和用户私有路径。
- 保留01-01资源所属权限、01-02受控媒体Cookie+Range、01-03内部服务鉴权与固定回调、01-04环境强密钥与bootstrap安全要求，不得降级来让测试通过。

## 3. 严格测试与判定

**必测：**
1. 用真实受控线程池/独立组件，验证首次创建和合法重试HTTP快速返回，后台最终完成或明确失败；测试必须实际经过Spring代理/执行器，不允许只Mock掉调度器。
2. 对一个task同时发起≥20次并发重试/重复点击：最多一个活动attempt；其他请求返回明确、稳定的状态；验证DB活动attempt数量与执行器实际启动次数（包括失败/排队状态）。
3. 相同幂等请求反复发送、不同客户端重复触发、请求线程和工作线程不同、线程池容量/拒绝、AI连接失败/503、意外异常、旧回调、服务重启模拟/剩余任务恢复或明确拒绝；分别记录执行证据和状态。
4. 非授权B用户与匿名用户不能重试A任务；管理员和已授权身份符合01-01规则，且被拒请求在**任何状态写入之前**被拒绝。
5. 对每次状态转移记录taskId/attemptId/时间戳，不记录密钥/私人完整路径。检查是否产生双执行、双事件、历史复核误删。
6. 重跑已有Spring JUnit（至少01-01 11项、01-02媒体、01-03内部7项、01-04安全启动11项）和AI Python 19项；构建前端并检查合成浏览器回归是否因API变化退化。Windows symlink不足则明示SKIP；不能用之前运行结果替代本轮测试。

**最低统计与证明：**报告实际用例数、通过/失败/跳过、HTTP状态、预期与实际、执行时间、队列大小及并发执行次数；避免把JUnit+HTTP+浏览器嵌套断言累加成独立测试数。错误后继续补测，保留第一次失败和最终有效结果的原始脱敏日志。
