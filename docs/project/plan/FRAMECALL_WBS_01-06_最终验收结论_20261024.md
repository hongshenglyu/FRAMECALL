## 2. 核心行为：已在隔离测试中证明

1. **同任务行锁与事务提交次序**：取消先提交`CANCEL_REQUESTED`后，晚到AI成功不得写`SUCCEEDED`、事件、结果路径或进度100。完成先提交则取消409，不触发远端取消；取消动作在事务外请求AI。
2. **取消结果与执行结束分别确认**：`TaskAttempt`增加`executionFinished`及`cancelOutcome`，原分析调用与取消调用**两个结果均明确结束**后才在限定条件下`CANCELLED`并释放active；任一不确定，保持占位和人工恢复标志，禁止重试。不能把HTTP取消确认等同于远端工作线程停止。
3. **请求和进度状态约束**：运行取消202，已结束取消409，重复取消不会重发远端调用；阶段+百分比双单调校验、重复通知无副作用、旧attempt/取消后回调拒绝；`COMPLETED`进度通知最多99，真正结果提交成功才写100。
4. **20并发混合请求**：10个取消请求202、10个重试409，保留一个当前attempt、一条原分析请求及一个远端取消；01-05的独立20并发重试回归仍是1接受19冲突。
5. **故障与历史保留**：隔离H2覆盖结果事务回滚、取消结算失败、503/超时/断联、重启后的安全占位、原历史事件及人工复核和媒体未变；Schema只验证H2增量迁移。生产MySQL SQL为`review-only`，未执行。
