## 成果二　问题优先级

| 必须修复 | 正式输入缺少比赛身份和覆盖范围。上传结果使用 UPLOAD-T 局部时间轴；实验须显式映射 matchId、partId、原片 PTS 与有效区间。全场从头观看，允许零事件区间和新增漏检事件。现有仅围绕候选或试标样片的导出无法建立召回率分母。 |
| 必须修复 | 旧 evaluate-predictions.mjs 会推断 sampleId，按真值顺序贪心匹配，超出时间容差仍可因窗口重叠命中。正式入口须执行成果三的协议，并拒绝缺失映射或未处理的测试分段。 |
| 必须修复 | 现有剪辑每次仅在 8 个时间分层中各挑一个代表。必须明确实际交给裁判的候选集合，逐项可回看。优先复用原片定位和统一窗口按需剪辑；若实际只交付抽选结果，单列其召回率、覆盖率与时长。禁止用全部 327 个检测和仅 8 段的观看成本描述同一效果。 |
| 必须处理的算法边界 | ByteTrack 在帧或 PTS 断点后新建 segment，剪辑函数只接受单一 segment，但上传路径把全部事件一次传入。对跨断点且两侧有候选的输入，按连续段分别规划窗口，保留唯一媒体标识。用一个双段用例验证两侧可播、互不跨段即可。 |
| 建议改进 | 同人高 IoU 当前只阻断运动项，仍可凭距离入选。用原 P3 的 630.730 秒实例和开发集真实双人重叠作正反对照；只在已证实同人配对可抑制且不会系统性丢失真实争抢时增加局部过滤。其余先用现有支持帧数、阈值、共享 ID 合并间隔减少重复，比较验证集漏检与回看量。 |

**人工真值。** 16 段已满足开题试标数量。新增 8 段由本人补标，用于覆盖较难争抢；S05 的“正常接近＋可见接触”交本人及裁判看原片。整场使用原片播放器和事件表即可。本人连续盲看全部有效时段，记录每次双人争抢的开始、首次可见接触、结束及参与者线索，同次争抢合并。记录困难无接触、存疑和范围外。持证裁判独立查看原片及全场覆盖、能补漏，再裁定分歧，保存原判、裁定、匿名复核人和版本。测试标注者不见算法候选，调参者不见测试标签。

**事件级实验。** 同一批轨迹、候选合并与窗口策略跑四组：仅归一化距离，距离＋接近速度＋相对速度变化，组合去接近速度，组合去速度变化。沿用当前底边中心距除以平均框高、径向接近速度、前后半窗相对速度向量差；现配置权重 0.55/0.25/0.20，缺项贡献 0，关闭特征按已启用权重归一。开发集定规则；验证集以事件 F1 选阈值，同分选回看时长低者。消融从已选组合仅关闭对应特征。保存输入、配置、代码版本后测试一次。

建议预注册同一比赛、同一连续源时间轴，候选峰值对首次可见接触，绝对误差 ≤2 秒（建议值，先用开发试标核定并在看测试前锁定）。同时争抢用区域/人物线索排除错配，无法区分的列存疑。最大化一对一命中数，再最小化总时间误差，以事件 ID 稳定破同分。每个真实接触至多一 TP，重复及无接触预测计 FP，未匹配接触计 FN。先匹配有效正例，再对仅落入预标存疑/范围外区间的预测单列忽略数。P=TP/(TP+FP)，R=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)；零分母记 NA。逐场报告并汇总计数求微平均。

**复核成本。** 对每个命中真值，以关联的可播放窗口完整覆盖人工起止作为完整；列完整数/全部命中数（缺片计不完整），并列完整数/全部正例。各连续段内裁边后取实际回看窗口并集，合计秒数除以有效比赛总秒数。未生成窗口不能记为零成本命中。若声明实际节省人时，另在同等素材上对照全片检索与候选复核，记录播放、暂停、定位和提交耗时，交叉分配场次或顺序；没有计时只报告观看时长占比。

## 成果四　下一阶段 Codex 任务清单

1. **筛场并冻结清单。** 以现有 8 个 ID 补齐完整性证据、分段偏移和 split。同步启动真人试标复核与全场初标；输出逐场覆盖表。缺场、缺裁判据实登记。
2. **实现正式真值导出与匹配。** 接受人工事件表和裁判裁定；用重复候选、相邻两事件、跨段同秒、全负场及存疑区间核算手工期望。发布冻结协议。
3. **跑一段有代表性的较长开发素材。** 先测约 8～10 分钟，记录内存、磁盘、耗时、PTS 连续性与回看覆盖。3 分钟已产出约 487 MiB，代码整读 detections 并保留 tracks，当前本机上传配置 2 GiB，登记中 12 个分段已超过此值。优先按原 part 离线处理，过长才切连续小窗，保存源 PTS、两侧上下文及唯一归属，检查边界不重计或漏段。若代表段通过，逐段完成首场并核全场覆盖；若内存或时限实测阻塞，再改对应读取环节。无需先上传一整场或立即重构流式架构。
4. **用开发真值修最小缺陷。** 处理跨段剪辑及所有交付候选的可回看性；复查同人双框、碎片和密集候选。留存修前后同段证据，验证集选参。MySQL 演示验收可并行。
5. **冻结后运行四组实验并打包。** 输出数表、逐场覆盖、少量 TP/FP/FN 与视角案例，复算一致后组装系统及必要数据并同步 GitHub。

值得最高能力模型专项判断的节点有两个。冻结前，给出比赛清单、匿名裁定样例和相邻事件，审查划分泄漏、匹配及复核成本分母；有开发真值后，给出重复框、真实重叠、ID 混接的成对样例与验证集差异，判断是否值得改变过滤规则。两次均需明确采用哪一方案及理由。
