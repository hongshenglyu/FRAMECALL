## 9. 修改与验收的固定操作流程
**每次开始**：明确WBS编号 → 确认Git/备份和最新源码版本 → Codex列将修改文件、关键调用链、回归范围及风险 → 只实现该WBS内容。
**每次结束**：代码diff审查 → 最小单测 → 相关三端契约/集成测试 → 真实输入验证（如适用）→ 把证据保存至 `docs/progress/<WBS>/` → 更新进度表、日志和剩余阻塞。
**任务状态定义**：`未开始`（无新工作）｜`进行中`（已有代码或材料在推进）｜`待验收`（完成实现但缺足够证据）｜`已完成`（验收条件满足）｜`阻塞`（依赖/素材/环境问题阻断）｜`延期`（目标日过而未关闭）｜`冻结`（决定暂不做）。
