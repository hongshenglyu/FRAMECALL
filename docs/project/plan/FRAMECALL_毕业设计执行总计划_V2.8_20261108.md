## 3. 数据集协议：不完整录像也有用，但评价口径必须清楚

**数据资产三级层次：** `eventId赛事 → matchId实际比赛 → partId时间顺序分段`；视频1/2/3编号按用户确认代表比赛时间先后顺序；一个比赛的分段永远不跨开发/验证/测试集合。

**数据用途分级：**
- **A类：经人工确认开赛至终场覆盖、分段衔接可靠的完整比赛。** 优先从A类选6—10场按全过程标注，支持正式整场事件级评估。
- **B类：明确缺少前段/尾段或其他区间的不完整比赛，但现存视频清晰可用。** 全部保留可用分段，参与YOLO检测/ByteTrack跟踪/候选规则调试、困难负样本标注；若做补充定量评价，只按**实际有完整标注的可观察时间区间**设分母，缺失时间不算漏检；结果与整场评估分开展示。
- **C类：无法正常读取、时间严重错乱的分段。** 暂不用于评价；保留文件与原因，除非修复成本低且确有必要。

**分段技术规则：** 不移动原片、不要求提前合并；每段保存原始PTS/帧索引/文件路径，形成局部时间轴。只有有事实依据时才建立连续全场时间映射；对缺失间隔显式标记`gap`。ByteTrack在断裂/镜头转换时允许重置ID，不能伪造跨文件同球员身份。抽样输入视频与日后真实处理结果都保留来源标记。

**标注范围：** 连续双人争抢一次事件；记录争抢开始、首次可见接触（没有接触则为空）、争抢结束；同次连续争抢的多次接触合并；分别标注可见接触、无接触争抢困难负样本、存疑/画面不可见。只定位候选，不分类犯规。先在真实片段试标10—20段并修订一页规范；之后6—10场整场标注，事件数据实生成。尽早落实裁判/裁判教学人员复核角色。

**分割与评估：** 按matchId分开发/验证/独立测试；6:2:2是比例参考，不是强制精确比例。若选6场可参考4/1/1、选8场可参考5/1/2、选10场可参考6/2/2，须兼顾赛事和机位；测试集只在规则锁定后做主测试，不用它调参。对于YOLO预训练权重不强制重新训练；“开发集”主要用于选规则阈值、分析漏检与视频管线验证。

## 6. 真实算法执行顺序（避免不必要的开发）

1. **视频读取器：** 为单个MP4输出真实帧/PTS/帧号、文件partId；原视频不修改；分段之间无需物理合并；只有可信时间关系才映射全场时间。
2. **YOLOv8：** 用合法预训练权重只检测球员等必要对象；保存检测框、置信度和时间轴；先选一小段足够真实的比赛视频，后扩至较长样本。
3. **ByteTrack：** 基于YOLO输出完成真正高/低分检测关联和跨帧ID维护；不允许旧Tracker“每帧新ID”冒充ByteTrack；遮挡/镜头切换后可重新编号。
4. **接触候选：** 对有共同时间覆盖的球员对计算归一化距离、相对速度变化、接近速度；非法dt/明显不可信轨迹跳过；输出多个候选，合并同一连续争抢；不是犯规概率。
5. **证据与复核：** 从原片按真实时间窗生成MP4/关键帧，复用已有系统界面，裁判保存结论，必要时导出PDF；只修改真正阻塞闭环的页面/接口。
6. **实验：** 同一测试集、同一匹配协议，比较距离基线和组合评分，并分别移除两个速度特征；事件级TP/FP/FN、Precision/Recall/F1、片段完整性、去重候选观看时长/可分析视频时长；分析遮挡、镜头运动、困难负例。

## 8. 最小验收规则与真正需要把关的六件事

1. **研究真实性：** Real模式不得回退成Mock成功；任何实验表格来自真实视频与真实预测文件。
2. **数据真实性：** 4场缺段如实标注、删除视频3后更新实际清单；部分视频可用但不可把未知区间当负样本或无漏检。
3. **跟踪真实性：** 有可观察的连续目标ID和轨迹，不接受简单逐帧ID伪装ByteTrack。
4. **视频证据真实性：** 帧图与MP4源于原录像，可播放且时间映射对应；不能用示意图代替。
5. **评价可信度：** 整场测试集冻结、同场不跨集合、清晰区分完整比赛评价和部分片段补充评价，指标可复算。
6. **项目可交付：** 核心链路在本机运行、GitHub有提交、论文文字与实际代码/结果一致。生产级TLS、多实例、灾备等非开题必要事项不阻断算法开发；若真实部署或学校要求涉及，再按实际需要处理。

| 开发进度停滞 | 连续两周没有真实检测/跟踪/候选可演示输出 | 暂缓非核心重构，聚焦单条真实视频闭环，保留实际失败原因 |
